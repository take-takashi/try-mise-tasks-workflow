# ADR 0001: mise File Tasks の Python ライブラリを `_lib` に置く

- 状態: [[ADR-0002]] により置き換え
- 日付: 2026-11-08

## 背景

Docs のタスクは、別のプロジェクトへフォルダー単位でコピーできるようにしたい。Python の共通処理はタスクの近くに置き、特別な検索パスの設定をせずに読み込みたい。一方で、ライブラリが mise のタスク一覧に現れることは避けたい。

## 決定

- Docs の Python ライブラリは `.mise/tasks/docs/_lib/` に置く。タスクからは `from _lib...` で読み込む。
- ライブラリの Python ファイルには実行権限を付けない。実行する File Task には、macOS / Linux で必要な実行権限を付ける。
- `_lib` は探索自体を除外されない。実行権限のあるファイルや TOML ファイルを置く場合は、mise に読み込まれる可能性がある。
- macOS / Linux では、一時的なタスクディレクトリを使ったテストで、タスク一覧への表示と Python の import を確認する。
- Windows は実行権限の判定方法が異なるため、対応を決める際に別途検証する。

## 理由と影響

タスクとライブラリをまとめてコピーでき、Python の検索パスを変更せずに import できる。macOS の mise 2026.11.3 では、実行権限のない Python ファイルがタスク一覧に現れず、実行権限を付けると現れることを確認した。mise の更新や環境による差はテストで検出する。

通常の新規ファイルには、作成方法や umask にもよるが、実行権限が付かないことが多い。既存ファイルのコピーや権限変更では例外があるため、ライブラリの実行権限がないこともテストで確認する。

`.lib` は探索を避けられるが、Python の検索パスを追加する必要があるため採用しない。共通ディレクトリの探索除外設定は、コピー先にも設定が必要になるため採用しない。
